# 브랜치와 커밋

`main`에서 짧은 기능 브랜치(`feat/기능명`, `fix/수정대상`)를 만든다. 검증한 기능은 PR을 통해 `main`에 병합한다. 커밋 하나에는 독립적으로 설명하고 확인할 수 있는 변경 하나를 담는다.

제목은 영어 타입과 한국어 설명으로 쓴다. 연결된 GitHub 이슈가 있으면 끝에 실제 번호를 붙인다. 타입은 `feat`, `fix`, `refactor`, `test`, `docs`, `chore` 중에서 고른다.

```text
feat: 문단 경계를 보존하는 청킹 구현 (#이슈번호)

변경: 어느 클래스에서 어떤 동작이 달라졌는지 적는다.
검증: 실행한 명령과 결과를 적는다.
Refs: docs/hpc-rag-spring-implementation-plan.md
```

문서만 바꾼 예시는 `docs: 브랜치와 커밋 메시지 규칙 추가`다.
